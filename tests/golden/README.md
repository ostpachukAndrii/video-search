# Золотий набір

Розмітка виконує дві ролі одразу, тому окупається двічі:

1. **Еталон для метрик** — на ній рахуються Recall@k, nDCG, чистота заперечення
   у сценаріях з `features/`.
2. **Калібрувальна вибірка для порогів фасетів** — фасет (`glasses`, `headwear`,
   `gender`) це косинус між ембедингом кропа й текстовим прототипом, і поріг
   «від якого значення вважаємо, що окуляри є» треба звідкись узяти.

## Формат

Кожен набір — тека з двома JSONL-файлами. JSONL, а не один JSON, свідомо:
розмітка дописується рядками руками і читається в diff по одному активу.

### `assets.jsonl` — що насправді зображено

```json
{"asset_id": "pg_001", "path": "media/pg_001.jpg", "media_type": "image",
 "labels": {"glasses": true, "gender": "male", "headwear": false},
 "objects": [{"label": "knife", "bbox": [0.41, 0.62, 0.03, 0.02], "area_ratio": 0.0006]}]}
```

### `queries.jsonl` — запит і чого від нього чекають

```json
{"query_id": "neg_001", "text": "чоловік без окулярів", "lang": "uk",
 "relevant": ["pg_002"], "forbidden": ["pg_001"],
 "expected_parse": {"must": [...], "must_not": [...]}}
```

`forbidden` — це не «нерелевантні». Це активи, поява яких у топі означає, що
заперечення **не спрацювало**. Саме ця множина робить вимогу п.11 вимірюваною:
перевіряємо не те, що знайшлося, а те, що не мало знайтися й усе одно знайшлося.

## Наповнення

Медіафайли в git не тримаються (див. `.gitignore`) — у репозиторії живе лише
розмітка. Самі файли кладуться в `media/` кожного набору при розгортанні.
Сценарії, яким потрібні реальні пікселі, пропускаються, якщо файлів немає, —
але перевірка цілісності самої розмітки працює завжди.

Цільовий обсяг прототипу: 200–400 зображень і 10–20 коротких відео.

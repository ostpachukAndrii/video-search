# vsearch — семантичний пошук по відео та фото

Прототип пошукової системи для розслідувань: слідчий описує сцену своїми
словами будь-якою мовою й отримує кадри та моменти відео, де вона є.
Працює в ізольованому контурі без доступу до інтернету.

Повний дизайн і обґрунтування рішень — [docs/architecture.md](docs/architecture.md).

## Головна ідея

Розділити «схожість» і «факти». Векторний пошук відповідає за семантику,
структуровані атрибути — за точні предикати:

```
"чоловік без окулярів біля червоної машини"
  → [1] розбір запиту          нормалізація мови + must / must_not
  → [2] жорсткий фільтр         glasses = false          ← тут вирішується заперечення
  → [3] гібридний retrieval     dense (SigLIP 2) + sparse (BM25) → RRF
  → [4] агрегація               регіони → кадри → сцени
  → [5] VLM-верифікація         лише спірний топ-30
```

Чому не просто CLIP: у векторному просторі `not X` лежить поруч із `X`, тому
заперечення схожістю не вирішується в принципі. Атрибути рахуються при
індексації й лягають у payload як індексовані поля — і «без окулярів» стає
точним фільтром, а не здогадкою.

## Швидкий старт

```bash
make venv       # оточення
make qdrant     # підняти Qdrant у Docker
make models     # завантажити ваги (ПОТРІБНА МЕРЕЖА — лише етап збірки)
make smoke      # згенерувати синтетичний набір і проіндексувати його
make test       # прогін CI
make doctor     # стан середовища: пристрій, ваги, Qdrant, набори
make wip        # backlog: які сценарії написані, але ще не реалізовані
```

Пошук і категорії з командного рядка:

```bash
PYTHONPATH=src .venv/bin/python -m vsearch.cli index ./фото --profile balanced
PYTHONPATH=src .venv/bin/python -m vsearch.cli search "червона машина вночі" -v

# власна категорія — самим лише текстом, без розмітки й негативів
PYTHONPATH=src .venv/bin/python -m vsearch.cli category-add removed_plates \
    "a car with removed license plates"
PYTHONPATH=src .venv/bin/python -m vsearch.cli search "авто" --category removed_plates
PYTHONPATH=src .venv/bin/python -m vsearch.cli categories -v

# як парсер зрозумів запит
PYTHONPATH=src .venv/bin/python -m vsearch.cli parse "чоловік без окулярів біля червоної машини"
# щільний пошук без LLM-розбору — ~30 мс замість ~1.6 с
PYTHONPATH=src .venv/bin/python -m vsearch.cli search "червона машина" --no-parse
```

### Виміряно

**M1**, набір smoke (24 зображення, balanced): Recall@10 — en 1.000, he 1.000,
uk 0.982; MRR 1.000; nDCG@10 0.907; чистота топ-5 0.983; затримка p50 24 мс.

**M3**, фасети через контрастні прототипи: категорія, додана самим лише
текстом, дає F1 0.955–0.981 — у межах 2–3% від ручно дібраних негативів.
Застосування до готового індексу — ~1200 векторів/с без читання пікселів.

**M4c**, відкритий словник: ознака береться з тексту запиту, а не з переліку.
Потрібний кадр піднімається на 2 позицію за запитом `pastel pink` і на 1 за
`beige`, хоча жодного з цих слів у системі не перелічено. Ціна — ~80 мс на
ознаку, і то на запит, а не на кандидата.

**M4b**, розбір запиту під GBNF-граматикою: 10/10 запитів шістьма мовами,
**нуль помилок парсингу**, медіана 1.6 с. Заперечення тримається українською,
польською, німецькою та івритом; подвійне заперечення й просторові відношення
(`inside`, `near`) витягуються.

**M4a**, набір binding (дзеркальні пари, де набір ознак кадру однаковий, а
звʼязування протилежне) — частка запитів без інверсій:
тільки кадри **3/9**, кадри+регіони 8/9, регіони ранжують + кадри доповнюють **9/9**.

**M4d**, піксельне плиткування на 117 реальних фото. Розмір плитки задається
в пікселях, а не часткою кадру (ADR-010):

| Схема | Плиток/кадр | Фото з сумками за «a handbag» |
|---|---|---|
| Сітка 2×2 | 5.0 | #53, впевненість 0% |
| **Плитка 288 px** | 24.0 | **#4, впевненість 100%** |

**M4e**, обумовлена детекція. Ті самі ваги Florence-2, різне лише те, чи
сказано моделі слово запиту: загальні пропозиції сумку й велосипед **не
знаходять**, `<OPEN_VOCABULARY_DETECTION>` знаходить обидва за 0.5–0.7 с.
Рамка 3.3% кадру дала 56.5% там, де цілий кадр дає 0.2%.

**M4f**, лексичний шар на Florence-2 `<OCR>`. Точний рядок `PXCLD-1624` з
монітора виводить кадр на перше місце, хоча щільний ембединг дає йому 0.0706
і ніколи не поставив би його першим. Символьні n-грами тримають одну помилку
OCR: запит `AA1Z34BB` знаходить напис `AA1234BB`.

### Реальні фото з перевіреною розміткою

Набір `real_photos`: 23 знімки, 13 запитів, **кожна мітка перевірена оком** на
самому знімку, а не виведена з видачі пошуку.

| | |
|---|---|
| середня позиція цілі | **2.9** |
| Recall@5 | 0.82 |
| Recall@10 | **1.00** |
| впевненість не суперечить порядку | 13 з 13 |

Найцінніше в наборі — **заборонені** активи: полиця з ромом і два кухлі пива
на запит «шампанське», жінка в окулярах для плавання на «чоловіка в
сонцезахисних», три кадри «жінка в чорному без дитини». Без таких пасток набір
показував би майже 100% і не міряв би нічого.

Синтетичні набори лишаються, але їхня роль інша: вони доводять, що конвеєр
працює наскрізь, і **не доводять нічого про якість** — тричі вони давали
протилежну відповідь.

### Інваріанти: тести, які не залежать від корпусу

Золотий набір із відомими відповідями легко почати підганяти. Тому поруч є
`invariants.feature` — **жодної розмітки, жодних очікуваних результатів**,
лише властивості для будь-якого запиту:

- показане число не суперечить порядку видачі;
- менший ліміт не змінює порядок, лише глибину;
- той самий запит дає той самий результат;
- профіль із фасетами дає індекс із фасетами;
- кожна відкинута умова названа вголос.

Три з пʼяти упали одразу й знайшли справжні дефекти.

## Веб-інтерфейс

```bash
make qdrant     # якщо ще не запущений
make demo       # наповнити індекс синтетичними наборами і підняти UI
# або, якщо індекс уже є:
make ui         # http://127.0.0.1:7860
```

Пʼять вкладок, кожна перевіряє свою частину:

| Вкладка | Що видно |
|---|---|
| **Пошук** | результати з **рамками** (🔴 обʼєкт детектора, 🔵 плитка 288 px, 🟢 кадр, 🟠 детекція під слово запиту), розбір запиту поруч, позначка жорсткого чи мʼякого режиму. Коли запит називає обʼєкти, кожна рамка підписана сутністю: `woman`, `child`, `bag` |
| **Розбір запиту** | як парсер зрозумів заперечення й просторові відношення — без самого пошуку |
| **Індексація** | індексація теки, вибір профілю, звіт із коефіцієнтом регіонів на кадр |
| **Категорії** | додати свою категорію текстом і застосувати до готового індексу |
| **Стан системи** | пристрої, ваги, Qdrant, ліцензії, золоті набори |

Що варто спробувати, щоб побачити механізми в дії:

- `червона фігура` без розбору — базовий щільний пошук, ~30 мс
- `чоловік без окулярів` з розбором — видно, як заперечення потрапляє в `must_not`,
  і як пошук деградує до мʼякого, бо людей серед фігур немає
- `אדם ללא משקפיים` — те саме івритом
- `червона сумка всередині чорного авто` — витягується відношення `inside`
- `a red circle` на наборі `binding` — дзеркальні пари, де перевіряється звʼязування

## BDD — це і є метрики якості

Сценарії з [features/](features/) не документація навколо коду, а вимірювальний
прилад: кожен формулює вимогу числом.

```gherkin
Сценарій: Окуляри виключаються, а не ігноруються
  Коли я шукаю "чоловік без окулярів"
  Тоді у топ-10 не має бути жодного кадру з міткою "glasses=true"
  І Recall@10 для мітки "glasses=false" має бути не менше 0.8
```

```bash
make test    # реалізоване — має бути зелено
make wip     # ще не реалізоване — має бути червоно
```

## Офлайн-контур

Тягнути файли можна **тільки** на етапі збірки образу. Середовище виконання
мережі не має взагалі.

```bash
make lock      # закріпити commit SHA і sha256 (потрібна мережа)
make models    # завантажити ваги (потрібна мережа)
make offline   # довести, що система працює із заблокованою мережею
make image     # зібрати образ і довести офлайн-контур усередині нього
```

Три рубежі, які тримають цю властивість:

1. `models/manifest.lock` — commit SHA замість тегів, sha256 на кожен файл;
   розбіжність валить збірку.
2. [`registry.py`](src/vsearch/backends/registry.py) приймає **лише локальний
   шлях, ніколи `repo_id`**: виклик `from_pretrained("microsoft/…")` мовчки
   працює на ноутбуці й падає тільки в контурі — найдорожчим способом.
3. [`netguard.py`](src/vsearch/backends/netguard.py) блокує зовнішні зʼєднання
   на рівні socket (loopback лишається — Qdrant слухає на localhost).

## Структура

```
features/        Gherkin-сценарії — специфікація і метрики водночас
src/vsearch/     пакет: реєстр моделей, профілі, ліцензії, золотий набір
eval/metrics.py  Recall@k, nDCG, чистота заперечення, перцентилі
tests/golden/    розмітка: еталон метрик і калібрувальна вибірка порогів
models/          лише manifest.lock; ваги приїжджають на етапі збірки
scripts/         fetch_models (build-фаза), verify_offline, check_licenses
```
